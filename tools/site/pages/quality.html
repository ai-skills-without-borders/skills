How skills are tested and approved

A skill is only as good as the evidence that it works somewhere other than where it was written. Every skill shows its level, where it has been tested, and who reviewed it.

The improvement cycle

A skill is never finished. Every educator who uses it can move it forward: a usage report, a suggested change, an edit, or a review from another school. Each step raises how much the next educator can trust it.

Maturity levels

A skill moves up only with evidence attached. It moves down if a tool change breaks it.

  1. DraftWritten or generalized, passes the automatic checks, not yet used for real teaching in this form.
  2. Tested at originUsed for real teaching at the institution that wrote it. The skill page says where it was used, who tested it, in which tools and when.
  3. Tested elsewhereUsed successfully at one or more other institutions, each with a usage report.
  4. ReviewedTested elsewhere and independently reviewed with the checklist by an educator from another institution.

Automated checks

Every change runs the library's build before anyone reviews it.

  • The skill's name, description and card are complete and consistent.
  • Every file the skill refers to exists.
  • No product-specific instructions that would stop it working in other AI tools.
  • Skills that include scripts say so, and work by reading where code can't run.
  • Every maturity level above Draft shows its evidence on the skill page. Levels above "tested at origin" also need usage reports from other institutions, or reviewers.

Approval rules

One approval is enough. The automatic checks catch format problems, and the maturity label shows how well tested a skill is, so changes never wait for a committee.

{{APPROVAL}}

Reviews by other institutions raise a skill's maturity label. They never block a change.

How to review a skill

Choose a skill from another institution, use it on a real task from your own teaching, then fill in the review. Reviews are public and credited.
