# Review checklist

For reviewers from an institution other than the skill's origin. A completed checklist, plus at least one usage report from another institution, moves a skill to `reviewed`.

Test the skill on a **real task from your own teaching**, in at least one tool, before reviewing.

## Fit
- [ ] The description names the task in words educators actually use, and it triggered when expected.
- [ ] It solves a real, recurring teaching task.
- [ ] It asked for the context it needed (learners, objectives, sources) instead of assuming.

## Safety and integrity
- [ ] It didn't invent sources, citations, figures, names, dates or framework wording in my test.
- [ ] It flagged missing information visibly instead of filling it.
- [ ] It asked for approval before producing the final output, or I had told it not to.
- [ ] It included an AI-assistance line (or asked for my institution's wording).
- [ ] It never asked for or reproduced identifiable patient or learner data.

## Pedagogy
- [ ] Outputs are aligned to learning objectives (IDs where available).
- [ ] Outputs are pitched at the learner stage I gave.
- [ ] The pedagogical choices are defensible; where I disagreed, I could steer it.

## Portability
- [ ] Nothing in it depends on one institution (names, templates, frameworks) unless supplied as a replaceable file.
- [ ] Nothing in it depends on one AI product. If it runs code, it explained what to do where code can't run.
- [ ] It worked in: ☐ Claude ☐ ChatGPT ☐ Gemini ☐ Copilot ☐ other: ____

## Documentation
- [ ] The card (`card.yaml`) is accurate.
- [ ] References load only when needed; `SKILL.md` is readable.

## Verdict
- [ ] Recommend `reviewed`
- [ ] Recommend changes first (list them in an issue)
